## 阶段 0：项目规范与开发日志

**范围**：根目录 `CLAUDE.md`、`docs/` 标准文件、日志 README 和当日日志。

**验收**：文档齐全；CLAUDE.md 链接路径正确；产品边界、日志维护方式与已确认需求一致。

## 阶段 1：应用骨架

**范围**：Vite + React + TypeScript、页面元信息、移动端应用壳、三入口导航、全局设计令牌和响应式基础。

**验收**：生产构建通过；三入口及 HOME 子栏目可切换；窄屏没有横向溢出；键盘焦点可见；开发服务器可启动。

## 阶段 2：DISCOVER

**范围**：少量上海精选推荐、体验详情和选择；Experiments 进度；确定性预设 Life Editor。

**验收**：推荐详情和选择可操作；实验进度可更新且刷新后状态一致；编辑器不调用外部 AI；首页不是无限滚动。

## 阶段 3：HOME / EVENTS

**范围**：活动列表与详情、组队信息、浏览和加入小队。

**验收**：可查看活动及队伍名额并加入；成功状态明确；重复操作受控；所有内容标识为演示。

## 阶段 4：HOME / MARKET

**范围**：创作者与商品列表/详情、购物袋、模拟下单确认。

**验收**：商品可加入或移出购物袋；数量和演示总额一致；订单确认明确说明不是真实购买；刷新后演示状态可恢复。

## 阶段 5：HOME / SPACE

**范围**：线下青年空间列表/详情、模拟预约或报名。

**验收**：详情信息完整；意向提交后出现清楚的模拟反馈；不声称产生真实预约。

## 阶段 6：IDENTITY

**范围**：Passport 与 Profile 合并视图、体验记录、徽章/兴趣/连接、年度时间线和纯文字反思。

**验收**：记录可新增和回看；不提供图片上传；Discover 到完成体验再到记录的路径连贯；刷新后数据一致。

## 页面深化追加批次

在首版功能阶段验收后，根据新增需求逐页深化。一次只实现一个页面范围，不把多个页面改动混在一个批次。

### D1：DISCOVER 个性化

**范围**：添加兴趣、可用时长、预算、社交方式四项本地偏好；依据结构化体验数据筛选当前精选；显示匹配数和无匹配时的重置入口；偏好跨刷新保留。体验详情可将所选体验带入 Identity 文字记录表单，用户提交文字后才写入档案。

**验收**：不同偏好能改变推荐集合；无匹配时明确解释并可恢复默认；原有详情、加入计划、实验和预设 Life Editor 操作仍可用；详情可跳转 Identity 并预填体验标题/地点，只有用户提交文字后才新增档案；不调用真实 AI、不新增无限流。

### D2：EVENTS 深化

**范围**：深化活动信息层级、适配用户偏好的展示和组队加入状态反馈；继续使用演示数据。

### D3：MARKET 深化

**范围**：深化创作者故事、商品比较和购物袋回访；继续保持不产生真实交易。

### D4：SPACE 深化

**范围**：深化空间类型/到访信息展示与预约意向管理；继续保持不产生真实预约。

### D5：IDENTITY 深化

**范围**：年度时间线支持关键词搜索、来源筛选和个人记录编辑；单独汇总 Discover 已选计划、Events 同行小队和 Space 预约意向为“下一步计划”，与已完成/已记录体验明确分区；继续只保存纯文字。

**验收**：搜索和来源筛选正确；个人记录编辑并刷新后保留；三类进行中状态能从各自本地状态读取且可继续跳转；计划不计入已完成时间线；不加入图片上传或真实 AI。

## 月度主题批次（E 批次，规划中）

方向：从"按周精选"扩展为"每月一个主题"的杂志式结构，形成「主题出现 → 线上发现 → 预设定向生成 → 现实尝试 → 线下活动 → 身份记录 → 下个月新主题」的闭环。所有批次一次只做一个，未开始前不写入"已完成"。

- **E1 品牌叙事开屏与主张屏**：进入时的主题开屏（主题名 + 大字标题 + 实拍图）与第二屏主张及具体玩法清单。当前应用已直接进入 DISCOVER，因此 E1 需作为可跳过的一次性叙事层实现，不恢复登录门槛。
- **E2 填空式标语与三问测试**：一组「去自然，不采秋 / 不玩泥巴 / 不打滚儿，等于白玩了」式填空题与括号注解；三个问题导向主题结果（奇幻主义 / 梦幻颠倒）。
- **E3 本月发现精选结构**：每月固定精选数量（地点 / 创作者 / 物件 / 活动 / 电影·专辑·杂志各 5 条），并接入现有偏好筛选。
- **E4 集市与活动入口**：本月好物推荐与地点、活动推荐入口，复用现有 MARKET / EVENTS / SPACE 组件。
- **E5 主题生成玩法**：生成测试角色结果与个人入场券。全部为确定性本地预设模板，界面必须标注演示，不调用真实 AI 或外部服务。（首版落地时，原计划的原型 / 路线人格 / 本月任务 / 推荐体验四块已按项目方要求删除，测试结果并入「梦游入场券」。）
- **E6 月度闭环与调研问卷**：本月低成本限时任务问卷（作为当月用户调研演示），以及月度状态与下月主题切换。

**共同验收**：不新增真实后端、AI、支付、预约或图片上传；所有生成结果为本地预设并明确标注演示；不引入无限滚动信息流；主题内容由用户提供前不预填虚构的活动信息。

**前置条件**：需要用户提供「异想集｜梦游仙境」的实际内容（见开发日志的待确认清单）。

## 阶段 7：整体验收与交付

**范围**：完整主流程回归、响应式与键盘检查、内容/隐私核对、更新文档和日志、启动开发服务器。

**验收**：生产构建通过；核心流程可完整演示；手机与桌面布局可用；遗留问题和未实现真实服务明确告知；提供本地访问地址。

## 阶段交接规则

每阶段结束时：运行窄范围检查并记录结果；检查本阶段的验收条件；更新当日日志。若发现问题，先修复并复验当前阶段。不得把未验证的工作描述为已完成。
