# 质量、安全与隐私标准

## 开发阶段检查

- 编辑后先运行最窄的构建、类型或行为检查；阶段结束时运行生产构建和该阶段验收项。
- 手动检查真实目标宽度下的布局、文字换行、底部导航、安全区和触控操作。
- 核对鼠标与键盘可达性、focus-visible、表单标签、成功/失败反馈和减少动态效果设置。
- 验证刷新后本地演示状态一致；验证重置演示后可以重新走通流程。
- 控制依赖数量；新增依赖前检查维护状态、许可和实际必要性。

## 隐私与安全

- 不持久化真实手机号，不实现短信验证和真实身份认证；演示流程如需手机号输入，必须只保存在内存中（不写入 localStorage、不上传）、限制长度与字符集，并在界面上明确标注为演示字段。
- 不将用户输入、记录或其他数据发送到第三方；首版不配置 API 密钥。
- 日志、截图和演示数据不包含真实个人信息、密码、令牌、密钥或环境变量内容。
- 用户输入作为文本渲染，不拼接为 HTML；对输入长度设置合理限制并处理空白内容。
- localStorage 内容必须可解析失败而不崩溃；不要把本地存储视作安全存储。
- 模拟购买、预约、活动和 AI 建议必须显式标注演示，不误导用户认为已产生真实交易或服务；不得出现真实支付、下单或跳转外部支付页面的能力。
- 票据（`unseen:tickets:v1`）只保存「票号 / 对应活动 / 是否确认保存」三个业务字段，不得写入姓名、昵称、手机号或支付信息；票面二维码必须写成占位（不可扫描），并标明不可入场。
- 「下载票据图片」必须是本地 canvas 生成、不发网络请求，且图片自身带「演示票 · 不可入场」标注；不得生成可扫码的凭证。
- 指向社交平台的入口：只用项目方确认过的账号地址，且必须 `target="_blank"` + `rel="noreferrer noopener"`，并去掉分享链接里的 `xsec_token` 等跟踪参数；未提供的渠道不得自编 URL 或用户名，只能给演示提示。（已确认：REVERIE 小红书 `https://www.xiaohongshu.com/user/profile/649917aa000000002b008d69`。）
- 社交地址只保留一个来源：`src/data/social.ts` 的 `xiaohongshuUrl`；主航栏的四个渠道标志（`src/components/SocialMarks.tsx`）、24H 任务的发布渠道与 ABOUT › CONTACT 的 Xiaohongshu 渠道都引用它，不在组件或数据里重复写 URL。四个标志为自绘单色简笔图形（不使用平台官方商标素材）；除小红书是真实外链外，抖音 / 公众号 / 微信都是按钮，点击只显示「待项目方提供」的演示提示（`role="status"`，4 秒后自动收起）。
- 不添加位置追踪、相机/照片权限、后台任务或未确认的外部网络请求。
